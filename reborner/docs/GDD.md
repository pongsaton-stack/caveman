## 1. แนวคิดหลัก

### ประโยคเดียว

ตัวเอกคนเดียวที่เริ่มจากไม่มีอะไรเลย เรียนรู้ท่าใหม่กลางสนามรบจากการเอาชีวิตรอด และเก็บมอนสเตอร์มาร่วมทางในโลกที่เสื่อมสภาพลงตามการกระทำของผู้เล่นเอง

### เสาหลักที่ดึงมาจากแต่ละเกม

| ต้นทาง | สิ่งที่ดึงมา |
|---|---|
| Romancing SaGa | ไม่มีเลเวล · ประกาย (เรียนท่ากลางสนามรบ) · LP · Free Scenario |
| Persona | เวลาเป็นทรัพยากร (ช่วงเวลาที่จุดพัก) · ตีจุดอ่อนได้เปรียบคิว |
| Chrono Trigger | ศัตรูมองเห็นบนแมพ · คอมโบระหว่างตัวละคร · ยุคที่เกี่ยวโยง (ทำเป็นแผนที่ 4 สถานะ) |
| Final Fantasy | ไทม์ไลน์คิว · customization ลึก · เวทย์เป็นสาย |
| Dragon Quest | เก็บมอนเข้าทีม · ตายแล้วเสียเงินครึ่งหนึ่ง · โทนอบอุ่น |

### หลักการที่ยึดตลอดทั้งเกม

1. **ทุกกลไกต้องแตะกลไกที่มีอยู่แล้ว** ห้ามมีระบบลอย
2. **การเรียนรู้มาจากอันตราย ไม่ใช่จากการทำซ้ำ** ฟาร์มมอนอ่อนต้องไร้ประโยชน์
3. **เชื่อเลขที่วัดได้ มากกว่าเลขที่คำนวณ**
4. **การป้องกันซื้อได้ การแก้ไขซื้อไม่ได้**
5. **ปรับทีละตัวแปร** สองตัวพร้อมกันจะทวีคูณกันเสมอ

### ฉากหลัง

โลกที่เคยมีอารยธรรมแบบปัจจุบันแล้วล่มสลาย เศษซากสมัยใหม่ (ที่เย็บกระดาษ ปืน โดรน) กระจายอยู่ในซากเมือง ส่วนดาบและเวทย์คือสิ่งที่ผู้รอดชีวิตสร้างขึ้นใหม่ — ฉากหลังนี้อธิบายว่าทำไมอาวุธจึงมีตั้งแต่ดินสอถึงเขี้ยวมังกร และทำไมกระสุนจึงหายาก

## 3. ระบบต่อสู้

### 3.1 คิว Action Value

ไม่ใช้เกจวิ่งแบบ ATB — ใช้ AV ซึ่ง deterministic และแสดงคิวล่วงหน้าได้ตรงเป๊ะ

```
AV = 10000 / SPD
AV ถัดไป = (10000 × ActionWeight / SPD) × PushMult
```

| แอ็กชัน | ActionWeight |
|---|---|
| ตั้งรับ | 0.5 |
| ใช้ไอเทม | 0.7 |
| โจมตีปกติ | 1.0 |
| ท่าพิเศษ | 1.0 – 1.4 |
| ท่าสูงสุด / อัญเชิญ | 1.6 |

`PushMult = 0.75` เมื่อแอ็กชันนั้นตีเข้าจุดอ่อน จำกัด 1 ครั้งต่อแอ็กชัน (กัน loop)

**UI ต้องแสดงคิวล่วงหน้า 8 ช่อง** — ถ้าผู้เล่นมองไม่เห็นคิว ระบบทั้งหมดนี้ไร้ความหมาย

### 3.2 สูตรความเสียหาย

```
Base       = (เวทย์ ? MAG : ATK) × SkillPower / 100
Mitigation = 100 / (100 + DEF × (1 − ignoreDef))
Damage     = Base × Mitigation × ElemMult × PosMult × ComboMult × Variance
```

| ตัวคูณ | ค่า |
|---|---|
| ElemMult | จุดอ่อน 1.5 · ปกติ 1.0 · ต้านทาน 0.5 · ภูมิคุ้มกัน 0 · ดูดซับ −1.0 |
| PosMult | ประชิดตีแถวหลัง 0.7 · อื่นๆ 1.0 |
| ComboMult | ปกติ 1.0 · คอมโบ 1.3 – 1.8 |
| Variance | สุ่ม 0.95 – 1.05 |

> **ห้ามเปลี่ยนเป็นสูตรลบ (`ATK − DEF`)** ในเกมที่ไม่มีเลเวล สเตตัสผู้เล่นโตไม่สม่ำเสมอ สูตรลบจะทำให้ดาเมจกลายเป็น 0 และเกมพังแก้ไม่ได้ สูตรหารเสื่อมแบบนุ่มนวล

### 3.3 ตั้งรับ

```
ลดดาเมจที่รับ 50%
Insight +8 เมื่อถูกโจมตีขณะตั้งรับ
ความเข้าใจท่าศัตรู ×2
ท่าถัดไปน้ำหนัก ×0.5
ActionWeight ของตัวมันเอง 0.5
```

**บรรทัดสุดท้ายสำคัญที่สุด** — ตั้งรับเสีย 42 AV และคืน 42 AV จากท่าถัดไป = เสมอตัวทางเทมโป ทำให้ดาเมจที่ลดกับ Insight กลายเป็นของแถมฟรี ก่อนหน้านี้ตั้งรับขาดทุนเทมโปและ**ไม่มีใครใช้เลย (0-5%)**

### 3.4 กริดและตำแหน่ง

- v1 ใช้แค่ **แถวหน้า / แถวหลัง** (กริด 3×3 เต็มรูปแบบเก็บไว้ v2)
- ท่าประชิดตีแถวหลัง = PosMult 0.7
- อาวุธที่มีตัวปรับกฎ `ยาวถึง` ไม่เสียโทษนี้
- ท่าสาย `ยิง` ไม่สนตำแหน่งเลย

### 3.5 คอมโบ

```
เงื่อนไขครบทุกข้อ:
  1. ตัวเอกกับมอนอยู่ติดกันในคิว (ไม่มีศัตรูคั่น)
  2. ความเชื่อใจ >= 3
  3. SP ของทั้งคู่พอ
```

ข้อ 1 คือหัวใจ — มันทำให้ SPD กลายเป็น**ปริศนา** ไม่ใช่แค่สเตตัสที่ยิ่งสูงยิ่งดี และทำให้ตั้งรับ (น้ำหนัก 0.5) กับคาถาเร่งคิว/หน่วงคิว กลายเป็นเครื่องมือจัดคิว

ศัตรูบางตัวก็ใช้กฎเดียวกัน (หมาป่าคู่) — **ศัตรูสอนกลไกให้ผู้เล่นด้วยความกลัวก่อนที่ผู้เล่นจะใช้เป็น**

### 3.6 ความตาย

| ใคร | เกิดอะไรขึ้น |
|---|---|
| **ตัวเอกล้ม** | จบการต่อสู้ทันที (แพ้) · เสียเงินครึ่งหนึ่ง · กลับจุดพักล่าสุด |
| **มอนล้ม** | เสีย LP 1 แต้ม · LP หมด = **หายไปถาวร** |

ตัวเอกไม่มี LP — เขาคือหลอดชีวิตจริงของเกม ส่วนมอนคือเดิมพัน

**การบรรเทา permadeath (จำเป็น):**
- LP 1 ต้องขึ้นสถานะ **"บาดเจ็บสาหัส"** ตัวใหญ่บนการ์ด และเตือนก่อนเข้าศึก
- ความคืบหน้าเก็บที่ **สายพันธุ์** ไม่ใช่ที่ตัว — มอนตายตอนใช้ท่าไป 22/30 ครั้ง รับตัวใหม่สายพันธุ์เดียวกันเริ่มที่ 22
- **มอนที่รับได้ต้องหาเจอง่ายเสมอ** (ดูข้อ 11.9)

### 3.7 หนี

```
ใช้ได้เฉพาะเทิร์นของตัวเอง · ActionWeight 0.8
โอกาส = clamp( 0.35 + (SPD เฉลี่ยฝ่ายเรา − SPD เฉลี่ยศัตรู) / 200 , 0.15 , 0.90 )
สำเร็จ → จบศึก ไม่ได้รางวัลใดๆ · ล้มเหลว → เสียแอ็กชัน
ติดสถานะ "ตรึง" → หนีไม่ได้
```

**ในเกมที่มี permadeath การหนีไม่ได้ = การบังคับให้เสียมอนถาวร** ข้อนี้ไม่ใช่ความสะดวก แต่เป็นความยุติธรรม · ผูกกับ SPD ทำให้ SPD มีงานที่สาม (คิว · คอมโบ · หนี)

### 3.8 เปิดท่าล่วงหน้า และ ขัดจังหวะ

```
ศัตรูในคิวช่องที่ 2-4 มีโอกาส 60% เปิดเผยว่าจะใช้ท่าอะไร
UI แสดง: ▼ชื่อท่า พร้อมตัวนับ ดาเมจสะสม / เกณฑ์

เกณฑ์ขัดจังหวะ = 15% ของ maxHP ศัตรู
สำเร็จ → ยกเลิกท่านั้น + AV ศัตรู ×1.4
ท่าที่เปิดไว้แล้วต้องใช้จริง ห้ามสุ่มใหม่ (ไม่งั้น UI โกหกผู้เล่น)
```

กลไกนี้เปลี่ยนคิวจาก**ข้อมูล**เป็น**การตัดสินใจ** — เห็นภัยมา แล้วเลือกว่าจะแข่งกำจัด ตั้งรับ หรือปล่อยผ่าน

**เกณฑ์ 15% มาจากการกวาดค่า:** 10% = ขัดได้ตลอดจนไร้ค่า (1.41/ศึก) · 30% = แทบไม่เคยเกิด (0.11) · 15% ให้ ~1 ครั้งต่อมินิบอส และแทบไม่เกิดกับมอนขยะ

### 3.9 ตบทิ้งบนแมพ

```
ถ้าศัตรูทุกตัวในกลุ่มมี tier <= ความชำนาญ − 10
→ ไม่เข้าฉากต่อสู้เลย ตัวเอกตบทีเดียวหายจากแมพ
→ ได้เงินเล็กน้อย · ไม่ได้ความชำนาญ · ไม่ได้ความเข้าใจ · ไม่ได้ Insight
```

**ไม่ต้องเพิ่มค่าคงที่ใหม่** — เกณฑ์ −10 คือจุดที่ `ThreatFactor` แตะพื้น (0.2) พอดี ซึ่งคือจุดที่มอนตัวนั้นให้อะไรกับผู้เล่นไม่ได้อยู่แล้วตามดีไซน์เดิม เราแค่เลิกเก็บเวลาผู้เล่นไปฟรีๆ

**วัดผลแล้ว:** ที่ prof 20 มอน tier 8 ถูกตบทิ้ง 200/200 ครั้ง · ที่ prof 10 ยังต้องสู้จริงทุกครั้ง · ที่ prof 30 มอน tier 25 ยังต้องสู้ — เส้นแบ่งคมและไม่มาเร็วเกินไป

ผลพลอยได้ที่สำคัญ: ภูมิภาคเก่ายังมีมอนเดินอยู่ (โลกดูมีชีวิต) แต่เดินผ่านได้สบาย — จำเป็นมากเพราะดีไซน์ Free Scenario บังคับให้กลับไปที่เดิมบ่อย

### 3.10 ลอบตี / ถูกลอบตี

```
เข้าหาศัตรูจากด้านหลังบนแมพ → AV ฝ่ายเรา ×0.4
ศัตรูแตะเราก่อน                → AV ศัตรู ×0.4
```

**ห้ามใช้ AV = 0** — ทดสอบแล้วให้ชนะ 100% กับ 7% ซึ่งคือการโยนหัวก้อยก่อนผู้เล่นได้กดอะไร ที่ ×0.4 ได้ 99% / 61% / 40%

ทำให้การเดินบนแผนที่เป็นการวางแผน และ**การหลบศึกกลายเป็นทักษะ** ซึ่งจำเป็นเมื่อลดจำนวน encounter ลง

### 3.11 ระบบสถานะ

| สถานะ | ผล | โจมตีระบบไหน |
|---|---|---|
| พิษ | เสีย HP 6% maxHP ต่อเทิร์นของตัวเอง | ทรัพยากร HP |
| เลือดไหล | เสีย HP 25% ของดาเมจที่รับล่าสุด ต่อเทิร์น | ลงโทษการโดนหนัก |
| หน่วง | AV ถัดไป ×1.3 | **คิว AV** |
| ตรึง | ห้ามสลับตำแหน่ง · ห้ามหนี | **กริด + หนี** |
| ผนึก | ใช้ได้เฉพาะท่าที่ไม่เสีย SP | **ทรัพยากร** |
| สับสน | 35% โจมตีพวกเดียวกัน | ความไม่แน่นอน |

```
อายุ 3 เทิร์นของตัวที่ติด (นับที่เทิร์นตัวเอง ไม่ใช่รอบรวม)
ซ้อนไม่ได้ — ติดซ้ำ = ต่ออายุ
โอกาสติด = ฐานของท่า × (1 − DEF / (DEF + 120))
```

**ไม่มีสเตตัสต้านทานใหม่** — ใช้ DEF ที่มีอยู่ ทำให้ DEF มีงานสองอย่าง และบิลด์สาย DEF มีเหตุผลขึ้นทันที

**ตั้งรับลดอายุสถานะทุกตัวลง 1 เทิร์น** — งานที่สี่ของตั้งรับ · **ติดสถานะให้ Insight +3** — สอดคล้องกับหลักที่ว่าทุกแหล่ง Insight คือสถานการณ์ที่แย่

> **"ผนึก" คือสถานะที่ออกแบบได้ดีที่สุด** มันบังคับให้ใช้ท่าพื้นฐานที่ไม่เสีย SP ซึ่งคือสภาวะที่ประกายเกิดบ่อยที่สุดพอดี — วัดแล้วอัตราประกายขึ้นจาก 7.7% เป็น 8.6% **ศัตรูที่ผนึกคุณ กำลังจัดฉากให้คุณพลิกกลับมา**

### 3.12 กฎสามข้อที่เคยค้าง — ตัดสินแล้ว

**SP ฟื้นหลังจบศึก 30% · เต็มเฉพาะจุดพัก**
ดันเจี้ยนกลายเป็นการเดินทางที่ต้องบริหารทรัพยากร และมันสร้างสถานการณ์ **"SP หมด ต้องใช้ท่าพื้นฐานใส่บอส" ซึ่งคือฉากประกายในตำนานของ SaGa**

**ศัตรูเสริมเข้าคิวที่ AV ×1.25 · เปิดท่าไม่ได้ในเทิร์นที่เข้ามา · ศัตรูรวมไม่เกิน 4 ตัว**
เข้าที่ AV 0 คือการโกง และไม่จำกัดจำนวนคือลูปไม่รู้จบ

**เป้าหมายตายก่อนถึงเทิร์นเรา → เล็งใหม่อัตโนมัติ ไม่เสียแอ็กชัน**
ถ้าไม่เหลือเป้าหมาย คืนเทิร์นให้เลือกใหม่ **ห้ามเผาแอ็กชันของผู้เล่นทิ้ง** — ความหงุดหงิดที่ไม่มีข้อดีใดๆ

## 4. ระบบเติบโตของตัวเอก

### 4.1 ความชำนาญ (ไม่มีเลเวล)

```
จบการต่อสู้ ต่อสายที่ใช้งาน:
  ถ้า ThreatFactor <= 0.4  →  gain = 0          ← สำคัญ ห้ามใช้ ceil
  ไม่งั้น                  →  gain = round( 3 × ThreatFactor / (1 + Prof/40) )

ATK  = 20 + WeaponProf × 1.6 + WeaponBase
MAG  = 20 + MagicProf  × 1.6 + StaffBase
HP   = 100 + Prof × 1.4
SP   = 34 + WeaponProf + MagicProf
DEF  = 20 + Prof × 0.5
```

ตัวเอกเรียนได้ทุกสาย ไม่มีคลาสล็อก แต่จะเชี่ยวจริงได้แค่ 2-3 สายใน 10 ชั่วโมง — มอนสเตอร์อุดที่เหลือ

**INT ยุบรวมกับ MAG แล้ว** อย่าสร้างสองตัว

> **ห้ามใช้ `ceil`** — `ceil` ทำให้ได้อย่างน้อย 1 แต้มเสมอแม้ ThreatFactor จะติดพื้น ซึ่งเปิดช่องให้ฟาร์มไม่รู้จบ และทำให้ประกายแทบไม่ทำงาน (ดู 4.5)

### 4.2 ThreatFactor — ตัวคูณกลางของทั้งเกม

```
ThreatFactor = clamp( 1 + (EnemyTier − Prof) × 0.08 , 0.2 , 2.5 )
```

ใช้กับทั้งการโตของความชำนาญ และโอกาสประกาย ผลคือ **สู้ของแข็ง = โตเร็ว, ฟาร์มของอ่อน = แทบไม่โต**

### 4.3 ประกาย (Glimmer)

```
P = 0.032 × ThreatFactor × (1 − LearnedRatio) × (1 + LUCK × 0.015)
```

Insight เป็นตัวสะสมคู่ขนาน — เมื่อเต็ม ท่าถัดไป**ประกายแน่นอน**

| เหตุการณ์ | Insight |
|---|---|
| ตั้งรับแล้วถูกโจมตี | +8 |
| สู้บอส (ต่อเทิร์นของบอส) | +6 |
| เพื่อนร่วมทีมล้ม | +10 |
| **HP ตัวเองต่ำกว่า 15%** | **+11** |
| HP ตัวเองต่ำกว่า 30% | +5 |
| โดนโจมตีหนัก (>18% maxHP) | +4 |
| ศัตรู tier >= ความชำนาญ (ต่อเทิร์น) | +3 |
| ใช้ท่ากับศัตรูที่แข็งกว่า | +3 |
| ตีจุดอ่อน | +2 |

```
เกณฑ์ Insight = 40
เศษยกไป 20% ของส่วนเกิน
หลังประกายจาก Insight เต็ม → ล็อกการสะสม 9 รอบ
```

**ทุกแหล่งคือสถานการณ์ที่กำลังแย่** — นั่นคือดีไซน์ ไม่ใช่ความบังเอิญ ประกายจะมาถึงตอนกำลังจะแพ้เสมอ

**จังหวะของโมเมนต์ (70% ของความสนุกอยู่ตรงนี้):**
1. เวลาหยุด ทุกอย่างซีดเหลือแต่ตัวละคร
2. สัญลักษณ์ประกายเหนือหัว
3. เสียงสติงเกอร์**ทับ**เพลงต่อสู้ (ห้ามตัดเพลง)
4. ชื่อท่ากระแทกเข้ามา
5. **ท่ายิงออกทันทีในเทิร์นนั้น ฟรี SP ดาเมจ ×1.5** ← ห้ามตัดข้อนี้
6. จบศึกขึ้นการ์ด "เรียนรู้ [ชื่อท่า]"

ข้ามได้หลังเห็นครั้งที่ 3-4 แต่**ปิดถาวรไม่ได้**

**การชี้ทาง:** ผู้เล่นเลือกได้ว่าจะประกายเป็นท่าอะไร ผ่านการถ่วงน้ำหนัก

```

ท่าที่ใช้เป็นพ่อแม่โดยตรง  ×4
ท่าที่ใช้อยู่กิ่งเดียวกัน   ×2

**กฎกันความหงุดหงิด:** ถ้า Insight เต็มแต่ไม่มีท่าให้เรียน ห้ามทิ้ง — แปลงเป็นโบนัสความชำนาญก้อนใหญ่

## 5. มอนสเตอร์ร่วมทีม

### 5.1 แบ่งหน้าที่ให้ชัด

| | ตัวเอก | มอนสเตอร์ |
|---|---|---|
| เติบโตด้วย | ความชำนาญ (ใช้แล้วโต) | เลเวล + ความเชื่อใจ |
| ชุดท่า | ยืดหยุ่นไม่จำกัด สร้างเอง | ติดตัวมา แก้ไม่ได้ |
| ประกายได้ | **ได้ — คนเดียวในเกม** | ไม่ได้ |
| บทบาท | ตัวแปร | ค่าคงที่ที่เปราะบาง |

### 5.2 อ่านท่า → ประตูสู่ทางเลือกสองทาง

```
เอาชนะมอน → ความเข้าใจครบ → เลือกทางเดียว:
   ยึดท่า      = ได้ 1 ท่า  เสีย 1 ช่องความจำ  (สลับได้)
   รับเข้าทีม  = ได้ทั้งชุด เสีย 1 ช่องปาร์ตี้  (บอส = 2 ช่อง)
```

**ความเข้าใจสะสมยังไง:** โดนท่า +1 · ตั้งรับใส่ท่านั้น +2 · ท่า "จับตา" ให้ทีม +2

| ประเภทท่า | ต้องเข้าใจ |
|---|---|
| ท่าธรรมดา | 3 |
| ท่าเด่น | 5 |
| **ท่าบอส** | **1 — แต่ผู้เห็นต้องยังยืนอยู่ตอนจบศึก** |

```
ช่องหน่วยความจำท่า = 4 + floor(Σ Prof / 150)   → 4 ถึง ~8
ท่าจากประกาย  : 0 ช่อง (เป็นตัวตน ถาวร)
ท่ามอนทั่วไป   : 1 ช่อง
ท่าบอส        : 2 ช่อง
```

### 5.3 สามชั้นของสกิลมอนสเตอร์

**กฎเดียวที่ตัดสินทุกท่า:**

> ถ้าตัวเอกจะทำท่านี้ ต้องมีอวัยวะหรือธรรมชาติที่มนุษย์ไม่มีไหม
> ไม่ต้อง → **ยึดได้** · ต้อง → **เฉพาะตัว**

| ยึดได้ (ใช้กฎของเกม) | เฉพาะตัว (หักล้างกฎของเกม) |
|---|---|
| ทุบทลาย · ผุบผลับ · ใส่จุดอ่อน · เข็มเจาะ · ชิงของ | แยกร่าง · ยืนตายไม่ได้ · กลืนแสง · ผนึกธาตุ · เรียกฝูง · ลอกท่า · จ้องหยุดเวลา |

**งบพลังต่างกัน:** ท่ายึดได้ต้องบาลานซ์โดยสมมติว่ามีครบทุกท่า (ผสมเสรี) → ต้องอ่อน · ท่าเฉพาะตัวมีพร้อมกันได้แค่ 4 (จ่ายด้วยช่องปาร์ตี้) → **แรงกว่าได้ 2-3 เท่า**

**กฎตรวจสอบ:** มอนที่รับเข้าทีมได้ต้องมีท่าเฉพาะตัวอย่างน้อย 1 ท่า ถ้าไม่มี ไม่มีเหตุผลจะเสียช่องปาร์ตี้ให้มัน → ย้ายไปกลุ่ม "รับไม่ได้"

**ชั้นที่ 3 — ท่าสืบทอด (เก็บไว้ v2):**
```
มอนอยู่ในทีม + ความเชื่อใจ >= 4 + มันใช้ท่าเฉพาะตัวครบ 30 ครั้ง
→ ตัวเอกประกายเป็นเวอร์ชันมนุษย์ พลัง 60-70% กินช่อง 0
→ ช่องปาร์ตี้กลายเป็นที่ฝึกหัดหมุนเวียน
```

### 5.4 ความเชื่อใจ (แทน Bond — ไม่ต้องเขียนบทเลย)

```
+1 ทุก 4 การต่อสู้ที่อยู่ในทีม
+1 ถ้าจบศึกโดยไม่ล้ม (จำกัด 1 ครั้งต่อ 3 ศึก)

rank 3 → ปลดล็อกคอมโบกับตัวเอก
rank 5 → วิวัฒนาการ (v2)
```

นี่คือจุดที่ประหยัดที่สุดในดีไซน์ทั้งหมด — ระบบ Bond เดิมต้องเขียนบทสนทนา 42 ฉาก อันนี้โตจากการเล่นล้วนๆ

### 5.6 แต้มสายพันธุ์ (v2)

```
มอนอยู่ในทีม + ชนะศัตรูสายพันธุ์เดียวกัน + มันไม่ล้มในศึกนั้น

### 6.2 ระดับอาวุธ

## 7. เวทย์มนต์และตำรา

### 7.1 สี่สาย (v1 เอาแค่ White + Black)

| สาย | ตัวตน |
|---|---|
| **White** | **โล่ ไม่ใช่หมอ** — กำแพงธาตุ (ลดดาเมจ 45% 3 เทิร์น) · ปกป้องชีวิต (กันการล้ม 1 ครั้ง) · ล้างสถานะ · คืน LP · **ไม่มีคาถาเติม HP เลย** |
| **Black** | ดาเมจธาตุตรง · AoE ตามรูปทรงกริด · เจาะเกราะ |
| Red (v2) | จัดการคิวและสถานะ — เร่ง/หน่วงคิว · **ใส่จุดอ่อน** · ลบบัฟ |
| Summoner (v2) | ครั้งเดียวต่อศึก · เผา Insight ทั้งหมด · พลัง = 110 + Insight × 2.8 |

> **White ต้องเป็นสายป้องกัน ไม่ใช่สายเติม HP** — การวัดผลพบว่าการฮีลเชิงตอบสนองในศึกที่สั้นและร้ายแรง **แพ้เสมอ** (ดูข้อ 11.7)
> การเติม HP เป็นหน้าที่ของไอเทม (ยาสมุนไพร I01/I03) ไม่ใช่ของเวทย์

**คาถาเรือธงของ Red คือ "ใส่จุดอ่อน"** — เปิด PushMult ให้ศัตรูที่ไม่มีจุดอ่อน ปลดล็อกเครื่องยนต์ทั้งหมดของเกม ต้องใส่ธาตุ**กายภาพ** (ฟัน/ทุบ) ก่อน เพื่อให้ทั้งปาร์ตี้ได้ประโยชน์ ไม่ใช่แค่ตัวเอก

### 7.2 ตำรา = ราก · ประกาย = กิ่ง

```
ตำรา  → ปลดล็อกโหนดรากของต้นไม้เวทย์
ประกาย → แตกกิ่งจากรากนั้นออกไปเอง
```

**ข้อนี้จำเป็น ไม่ใช่ของแถม** — ถ้าเวทย์ประกายไม่ได้ ผู้เล่นสายเวทย์จะเลิกประกายถาวรและระบบลายเซ็นของเกมตายเงียบๆ (ดูข้อ 11.6)

### 7.3 การดรอปตำรา

```
ตำราพื้นฐาน (ฮีล ธาตุระดับ 1)  → ร้านค้า / รางวัลเควส 100%
ตำราระดับกลาง                → ดรอป 15-25% จากมอนที่สู้ซ้ำได้
ตำราชั้นสูง + อัญเชิญทั้งหมด    → บอสดรอปแน่นอน 100%
```

> **กฎเหล็ก: อะไรที่ขาดแล้วเกมพัง ห้ามเป็น RNG**

### 7.4 เศรษฐกิจช่วงเวลาที่จุดพัก

```
ตำราเป็นไอเทมถาวร ใครอ่านก็ได้ ต้องมีความชำนาญสายนั้นถึงเกณฑ์
อ่านได้เฉพาะที่จุดพัก

จุดพักแต่ละครั้งมี 3 ช่วงเวลา
ใช้ 1 ช่วงเวลา = อ่านตำรา 1 เล่ม (หรือกิจกรรมอื่น)
ทั้งเกมมีจุดพัก ~14 ครั้ง = 42 ช่วงเวลา
```

ตำรา 28 เล่ม × 1 ช่วงเวลา = 28 → ตึงพอดี **ให้ตำราพื้นฐาน 8 เล่มแรกอ่านฟรีไม่กินช่วงเวลา**

**ห้ามให้การทำอาหาร (v2) กินช่วงเวลาที่จุดพัก** — ทรัพยากรนี้ตึงอยู่แล้ว

## 8. โครงเรื่องและ Free Scenario

### 8.1 Event Counter แทนบท

```
EC เพิ่ม 1 ต่อการจบเควสหลัก 1 เควส (เควสรองไม่เพิ่ม)
เควสหลักที่มีในเกม: 24 · ต้องจบ ~14 เพื่อปลดล็อกตอนจบ

EC 0-4    องก์ 1  โลกยังปกติ
EC 5-10   องก์ 2  รอยแตกเริ่มปรากฏ
EC 11-16  องก์ 3  โลกเสื่อมสภาพชัด
EC 17+    ตอนจบเปิด
```

ผู้เล่นคนหนึ่งจะเห็นแค่ 14 จาก 24 เควส — ทั้งความเสียดายและเหตุผลให้เล่นซ้ำ และตัดปริมาณเนื้อหาที่ต้องขัดจนเนียนลงเหลือ 60%

### 8.2 ตารางข้อมูลเควส

```
quest_id | region | ec_min | ec_max | prereq | mutex_group |
enemy_tier | unlocks_char | sets_world_flag
```

- **`ec_max` = เควสหมดอายุ** พร้อมผลกระทบต่อโลก (หมู่บ้านถูกทำลาย ฯลฯ) — กลไกนี้สร้างน้ำหนักการตัดสินใจได้มากที่สุดต่อบรรทัดโค้ด
- **`enemy_tier` ผูกกับ EC ไม่ใช่สเตตัสผู้เล่น** — เร่ง EC เร็วเกินไปโดยไม่ฝึก = โลกแข็งเกินตัว

### 8.3 กลเม็ดสำหรับคนเดียว

```
3 ภูมิภาค × 3 สถานที่ย่อย = แผนที่ 9 ผืน
แต่ละผืนมี 4 สถานะตาม EC:
  ชุดบทสนทนา NPC · โทนสี/อากาศ · ตาราง encounter · prop ที่เปิด/ปิด
= 36 "สถานที่" ที่รู้สึกต่างกัน จากอาร์ต 9 ชุด
```

การกลับไปที่เดิมแล้วเห็นมันเปลี่ยนไป ให้ความรู้สึกเหตุ-ผลข้ามเวลาแบบ Chrono Trigger โดยไม่ต้องวาด tileset เพิ่ม

### 8.4 ตัวละครและตอนจบ

- ตัวเอก 1 คน (คงที่) + **NPC ร่วมทางที่ไม่ลงสนามรบ 2-3 คน** — ได้ตัวละครให้ผูกพันโดยไม่ต้องบาลานซ์และไม่ต้องทำอนิเมชันต่อสู้
- ตอนจบตัดสินจาก: สาย mutex ที่เลือก × มอนที่รับมา × EC ตอนเข้าตอนจบ → **4 ตอนจบ**
- ดันเจี้ยนสุดท้ายใช้ร่วมกัน ต่างกันแค่ฉากปิด 5-8 นาที (combinatorics ไม่ใช่เขียนสี่เรื่อง)
- New Game+: ยกความชำนาญมา 50% และแสดง `ec_max` ของทุกเควส · สมุดสะสมการเก็บ (สกิล/ไอเท็ม/มอน) ข้ามรอบ → ครบ 100% ปลดตอนจบ "คืนร่าง" (ดู `docs/STORY_DRAFT.md` 4.5)

### 8.5 บอสสุดท้าย

**ผู้ที่นับเหตุการณ์** — ตัวตนของมันคือ Event Counter เอง ยิ่ง EC สูงยิ่งแรง

> ร่างตัวตน Rion + ฉากเปิดเรื่อง + ผู้ที่นับ: `docs/STORY_DRAFT.md` (ร่าง · ยังไม่ล็อก)

## 11. บทเรียนจากการวัดผล — ห้ามแก้ย้อน

> ทุกข้อในนี้มาจากการวัดผลจริง (รวมกว่า 3,000 การต่อสู้จำลอง)
> ถ้าอนาคตอยากเปลี่ยน ให้อ่านข้อนี้ก่อนว่าทำไมมันถึงเป็นแบบนี้

**11.1 — "ครั้งที่ต้องตี" เป็นตัวชี้วัดที่ผิด**
เวิร์กบุ๊กคำนวณจากผู้โจมตีคนเดียว แต่ในสนามมี 3 ตัวรุมตี ตัวชี้วัดที่ถูกคือ **รอบต่อการต่อสู้**

**11.2 — เชื่อเลขที่วัดได้ ไม่ใช่เลขที่คำนวณ**
`glimBase 0.06` ควรให้ 6% แต่วัดได้ 12.8% ปรับเป็น 0.032 จนวัดออกมา 3-4% **ไม่ต้องไล่หาสาเหตุ ปรับจนตัวเลขที่วัดได้เข้าเป้า**

**11.3 — ตั้งรับตายเพราะขาดทุนเทมโป**
เสีย 42 AV เพื่อประหยัด 21 AV → ไม่มีใครใช้ (0-5%) แก้ด้วยการทำให้ท่าถัดไปน้ำหนักครึ่งเดียว = เสมอตัว แล้วมันโผล่มา 7% เฉพาะตอนอันตราย **ซึ่งถูกแล้ว — ตั้งรับควรเป็นเครื่องมือตามสถานการณ์**

**11.4 — ท่าใบแรกต้อง req ต่ำ**
ที่ prof 10 ประกายเกิดไม่ได้เลยเพราะท่าแรกต้องการ prof 15 ผู้เล่นภูมิภาค 1 จะไม่เคยเห็นกลไกหลัก

**11.5 — เวทย์ทำให้เกมยากขึ้น ไม่ใช่ง่ายขึ้น (กราฟตัว U) — ⚠️ ข้อนี้ถูกหักล้างบางส่วนแล้ว ดู 11.19**

**11.6 — เวทย์ฆ่าประกาย ถ้าเวทย์ประกายไม่ได้**
วัดครั้งแรก: ตัวเอกใช้ท่าดาบ **0 ครั้ง** เพราะศัตรูอ่อนแอต่อไฟ เวทย์ชนะขาดทุกเทิร์น → อัตราประกาย 0.0% แก้โดยให้สายเวทย์แตกกิ่งได้

ฮีล 35% ของ HP เป้าหมาย = 24 หน่วยใส่ตัวที่ HP 70 แต่ศัตรูตีทีละ 70 → เสียเทิร์นเต็มใบเพื่อซื้อเวลาไม่ถึงครึ่งเทิร์น อัตราชนะร่วงจาก 74% เหลือ 32% **→ White ต้องเป็นสายป้องกัน**

**11.8 — LP ฟื้นทุกจุดพัก = permadeath ไม่เคยเกิดขึ้นเลย**
ทดสอบ 30 ศึก: **0.0 ครั้ง** ภัยคุกคามเป็นของปลอมทั้งหมด

**11.9 — วงจรมรณะเกิดจากการหาของทดแทนไม่ได้ ไม่ใช่จากการสูญเสีย**
LP เหมือนกัน ต่างแค่ความง่ายในการหามอนใหม่ (45% → 20%) → วงจรมรณะ 28% → 38% **มอนที่รับได้ต้องหาเจอง่ายเสมอ**

**11.10 — ราคายาไม่ใช่ตัวแปร**
ขึ้นราคา 4.7 เท่า ผลไม่ขยับ เพราะเงินไม่ขาดแคลนและของดรอปเลี้ยงระบบไว้หมด **ตัวแปรจริงคืออัตราดรอปกับรายได้ต่อศึก**

**11.11 — ปรับทีละตัวแปร**
เพิ่ม HP ×1.8 พร้อม ATK ×1.25 → อัตราชนะร่วงจาก 92% เหลือ **3%** สองตัวนี้ทวีคูณกัน (สู้นานขึ้น × เจ็บหนักขึ้น)

**11.12 — recalc ผ่านไม่ได้แปลว่าเลขถูก**
การแทรกคอลัมน์ใน Excel ทำให้สูตรที่อ้างคอลัมน์เดิมไม่เลื่อนตาม ครั้งหนึ่งช่องดาเมจกลายเป็น `ราคา × ATK` โดยไม่มี error เลย **ตรวจค่าจริงเสมอ ไม่ใช่แค่ตรวจว่าไม่มี error**

**11.14 — เปิดท่าล่วงหน้าต้องเปิดก่อนถึงคิว ไม่ใช่ตอนถึงคิว**
ครั้งแรกท่าถูกเปิดตอนศัตรูเป็นคิวปัจจุบันพอดี ไม่มีใครทันขัด → ขัดจังหวะ 0.00 ทุกศึก

**11.15 — ตรรกะที่เขียนซ้ำสองที่จะแตกต่างกันเสมอ**
โค้ดเปิดท่าอยู่ใน `next()` แต่ตัวจำลองมีลูปเทิร์นของตัวเองที่ไม่เรียก `next()` → ฟีเจอร์ไม่เคยรันในโหมดวัดผล แม้แก้บั๊กแรกไปแล้ว **ตอน port เข้า Godot ต้องมีลูปเทิร์นเดียวเท่านั้น**

**11.16 — ให้เครื่องมือใหม่กับผู้เล่น ต้องคิดค่าชดเชยเสมอ**
ขัดจังหวะทำให้มินิบอสง่ายขึ้นจาก 83% เป็น 98% ต้องขยับ ATK โกลเลม 176 → 205

**11.17 — ลอบตีแบบ AV = 0 คือการโยนหัวก้อย**
ชนะ 100% เมื่อลอบสำเร็จ กับ 7% เมื่อถูกลอบ — ผลถูกตัดสินก่อนผู้เล่นกดอะไรเลย

**11.18 — เงื่อนไข AI ที่แคบเกินทำให้ฟีเจอร์ดูเหมือนพัง**
ล้างสถานะไม่เคยถูกใช้ (0.00) เพราะรอให้ติดพร้อมกัน 2 สถานะ ลดเป็น 1 แล้วขึ้นเป็น 0.51/ศึก **ก่อนสรุปว่าฟีเจอร์ไม่เวิร์ก ให้ตรวจว่า AI มีโอกาสใช้มันจริงไหม**

**11.19 — ตัวเลขอัตราชนะทั้งหมดคือขอบล่าง ไม่ใช่ความยากจริง** ⚠️ สำคัญที่สุด

ศึกหมาป่า ตัวเอกสายเวทย์:

| ผู้เล่น | อัตราชนะ |
|---|---|
| AI จำลอง (มีตัวเลือกซัพพอร์ต) | **49%** |
| เล่นเป็น: ทุ่มดาเมจอย่างเดียว | **100%** |

ต่างกัน 51 จุด จากการตัดสินใจอย่างเดียว ไม่ได้แก้ตัวเลขอะไรเลย

AI จำลองเสียเทิร์นไปกับกำแพง ล้างสถานะ และตั้งรับ ในศึกที่สั้นและร้ายแรงซึ่งควรทุ่มดาเมจอย่างเดียว **แอ็กชันของตัวเอกกว่าครึ่งไม่ทำดาเมจเลย** (อัตราส่วนดาเมจออก/เข้า 0.87 เทียบกับ 1.27 ตอนไม่มีเวทย์)

ผลที่ตามมาสำหรับทั้งเอกสารนี้:
- **ทุกอัตราชนะที่บันทึกไว้คือ "ผู้เล่นที่เล่นไม่เก่ง"** ผู้เล่นจริงที่เข้าใจระบบจะเจอเกมที่ง่ายกว่านี้มาก
- **กราฟตัว U ในข้อ 11.5 อาจเป็นสิ่งประดิษฐ์ของ AI ไม่ใช่คุณสมบัติของดีไซน์** ต้องยืนยันด้วยคนเล่นจริง
- ตอนปรับสมดุลจริง **ต้องเล็งที่ผู้เล่นที่เล่นเป็น** ไม่ใช่ที่ตัวเลขจากตัวจำลอง

**11.20 — ตัวจำลองที่ไม่ครบระบบ จะโทษดีไซน์ผิดตัว**
ตัวจำลองการเติบโตรุ่นแรกไม่ได้จำลองระบบ Insight เลย จำลองแค่การสุ่มที่ผูกกับช่องว่าง tier → สรุปว่า "ประกายแทบไม่ทำงาน ได้แค่ 1 จาก 6 ท่า" และเกือบทำให้ผมไปดัน tier ศัตรูทั้ง 45 ตัวโดยไม่จำเป็น

พอใส่ Insight (ซึ่งใช้สัญญาณวิกฤตจริง ไม่ใช่ช่องว่าง tier) ด้วยอัตราที่วัดได้จากต้นแบบ → ได้ **6 จาก 6 ท่า** ดีไซน์ไม่เคยผิด ตัวจำลองต่างหากที่ไม่ครบ

**ก่อนแก้ดีไซน์เพราะตัวเลขไม่สวย ให้ตรวจก่อนว่าตัวจำลองครบทุกระบบหรือยัง**

**11.21 — Insight มีสองชนิด ต้องแยกให้ขาด**
crisis (เพื่อนล้ม · HP วิกฤต · โดนหนัก) เกิดเป็นครั้งๆ ไม่โตตามความยาวศึก ส่วน ambient (สู้บอส · ใช้ท่ากับศัตรูแข็งกว่า) สะสมทุกเทิร์น วัดได้ว่า ambient กิน 56% ของ Insight ในศึกมินิบอส → Insight กลายเป็น **นาฬิกาจับเวลาศึก** ไม่ใช่มาตรวัดวิกฤต: โกลเลมที่ชนะ 93% (ไม่อันตรายเลย) กลับได้ Insight เต็ม 2.48 ครั้ง **ambient ต้องต่ำเสมอ ยกเว้นบอสซึ่งเป็นโรงงานประกายโดยเจตนา**

**11.22 — ศัตรูเล็งตัวที่ HP น้อยที่สุด = มอนร่วมทีมเป็นแท้งก์ = ตัวเอกแทบไม่โดนตี**
Insight ที่ผูกกับ HP ของตัวเอกอย่างเดียวจึงแทบไม่ยิง ตัดค่า ambient แล้ว Insight เต็มลดเหลือ 0.00 ทุกช่อง แก้ด้วยการให้ Insight ตอบสนองต่อ **ความอันตรายของทั้งทีม** (เพื่อนล้ม +18 · เพื่อนเจ็บหนัก +8) ซึ่งตรงกับธีม — การเห็นเพื่อนร่วมทางกำลังจะตายคือวิกฤตเต็มรูปแบบ **ผมประมาณการพลาดสองรอบติดเพราะคำนวณบนกระดาษแทนที่จะดูกลไกจริง**

**11.23 — `FIGHTING_BOSS` เป็นหน้าผา ไม่ใช่เส้นตรง**
บอสทำแค่ ~3 เทิร์นต่อศึก ค่า 9 ได้ Insight เต็ม 0.30/ศึก แต่ 10 ได้ 0.87 เพราะข้ามเกณฑ์ 40 ในเทิร์นที่ 3 พอดี **เลือกต่ำกว่าเป้าดีกว่าเกินเป้าสองเท่า**

**11.24 — class_name ซ้ำพังทะเบียนคลาสทั้งโปรเจกต์**
`BattleTest.gd` ถูกทับด้วยเนื้อหาของ `Battle.gd` → สองไฟล์ประกาศ `class_name Battle` → ทุกคลาสหายหมด error "Could not find type X" ท่วมจอทั้งที่ไฟล์ X ไม่ได้ผิด **เห็น error ท่วมจอแบบนี้ให้สงสัย class_name ซ้ำหรือไฟล์ core หายก่อนเสมอ**

**11.25 — ไฟล์ unsaved ทำให้ตัวเลขไม่เปลี่ยน**
แก้โค้ดแล้วรันได้ตัวเลขเดิมเป๊ะทุกช่อง สาเหตุคือไฟล์ค้าง `unsaved(*)` Godot รันเวอร์ชันบนดิสก์ **Sim พิมพ์บรรทัด "เวอร์ชัน:" ไว้บนสุดแล้ว — ดูทุกครั้งก่อนอ่านตัวเลข**

**11.26 — พอร์ตตรรกะเป็น Python แล้วเทียบกับ Godot จริงก่อนจูน**
ผมรัน Godot ไม่ได้ จึงพอร์ต `Battle.gd` บรรทัดต่อบรรทัดเป็น Python แล้วปิดฟีเจอร์ใหม่ เทียบกับผล Godot รอบล่าสุด (หนอนหิน 136 vs 137 AV · หมาป่า 0/5/42% vs 0/3/41%) ตรงแล้วจึงเชื่อตัวเลขที่พอร์ตทำนาย **ห้ามจูนด้วยพอร์ตที่ยังไม่ได้เทียบกับของจริง**

**11.27 — เครื่องมือใหม่ต้องชดเชยที่ศัตรู ไม่ใช่ที่เครื่องมือ (ยืนยัน 11.16 อีกครั้ง)**
หลังใส่คอมโบ+ขัดจังหวะ โกลเลมชนะ 96-99% ลด `COMBO_MULT` 1.5 → 1.15 แล้วโกลเลมยังชนะ 95-98% — ตัวคูณคอมโบแทบไม่มีผล ปัญหาคือโกลเลมอ่อนเกินต่อชุดเครื่องมือใหม่ แก้ที่ CSV: ATK 135→200 · HP 400→480 ได้ 71-81%

**11.28 — บอสที่ชนะไม่ได้ อาจไม่ใช่บอสที่แรงเกิน แต่คือระบบที่ขาด**
แผนที่แรกเผยว่าบอสภูมิภาค 1 ชนะได้แค่ 0-4% แม้ prof 20 ทางแก้ที่ง่ายคือลดพลังบอส แต่ตัวเลขบอกว่าถือมีดทำครัว (ค่าอาวุธ 14) ชนะ 2-10% ส่วนอาวุธ tier 1 (ค่า 28) ชนะ 74-91% — **บอสออกแบบถูกแล้ว แต่แผนที่ไม่มีทางได้อาวุธใหม่** แก้ด้วยหีบหลังฝูงหมาป่า ไม่ได้แตะค่าบอสเลย
และบอสต้องนับจากธง `is_boss` ไม่ใช่จาก tier — ราชาหนอนเถ้า tier 20 ต่ำกว่าเกณฑ์บอส 40 เลยไม่ได้เป็นโรงงานประกาย ทั้งที่เป็นบอส · และบอสต้องไม่ถูกตบทิ้งบนแมพเด็ดขาด
**ตัวจำลองที่วัดศึกเดี่ยวๆ มองไม่เห็นปัญหาการเดินทาง — ต้องจำลองเส้นทางของผู้เล่นด้วย**

**11.29 — ตัวเลขที่วัดก่อนแก้ระบบ ใช้เป็นเป้าหลังแก้ไม่ได้**
"มีดทำครัวชนะ 2-10%" ใน 11.28 วัด**ก่อน**ให้บอสนับจากธง `is_boss` พอบอสเป็นโรงงานประกายจริง ตัวเอกได้ Insight เต็ม 1-2 ครั้ง/ศึก มีดจึงชนะ ~5-10% (prof 16) · ~20% (prof 20) · ~30-40% (prof 22) ใน Godot 4.7.1 จริง (ปิดธงชั่วคราวแล้วกลับไปได้ 1/3/13% = ยืนยันสาเหตุ) ไม้เบสบอล (28) ยังได้ ~55/84/91% ตรงเป้า
**ตัดสินแล้ว: ยอมรับตัวเลขใหม่** — ช่องห่างมีด ~20-40% กับไม้เบสบอล ~80-90% ยังเป็นประตูอาวุธที่ชัด และจูนบอสลงจะกระทบไม้เบสบอลด้วย **เมื่อแก้ระบบใดก็ตาม ต้องวัดเป้าที่เกี่ยวข้องใหม่ทั้งหมด ไม่ใช่แค่ตัวที่ตั้งใจแก้**

**11.30 — ตาราง "ช่องปาร์ตี้ตาม EC" เดิมทำให้ภูมิภาค 1 ชนะไม่ได้**
ตารางเดิมให้ EC 0 = 1 ช่อง (ตัวเอกคนเดียว) · วัดใน Godot 4.7.1 (200 ศึก/ช่อง · prof 8-22 · มีด 14 และไม้เบสบอล 28):
ตัวเอกคนเดียว — ค้างคาวเงา x2 **0%** · หมาป่าคู่ **0%** · บอส B1 **0%** (สไลม์/หนอนหินยัง 96-100%)
ตัวเอก + มอน 1 ตัว — บอส B1 0-31% · ตัวเอก + มอน 2 ตัว (หนอนหิน+ค้างคาว) — บอส 55-85% ตามเป้า
**ตัดสินแล้ว (25 ก.ย. 2026): เริ่มเกมพร้อมมอน 2 ตัว** ช่องนับเฉพาะมอน: EC 0 = 2 · EC 6 = 3 · EC 11 = 4 (`data/party_slots.csv`) · ตัวเลขสมดุลทั้งหมดในหมวด 10 วัดด้วยมอน 2 ตัวอยู่แล้ว จึงใช้ได้ต่อ
**ก่อนลดจำนวนพวกในเนื้อเรื่อง ต้องวัดศึกที่ต้องสู้จริงด้วยทีมขนาดนั้นก่อน**

**11.13 — โหมดจำลองซ่อนบั๊กที่โหมดเล่นเองเจอ**
เทิร์นของมอนในทีมทำหน้าจอคำสั่งพัง แต่ตัวจำลองข้ามไปเอง **ต้องทดสอบเส้นทางที่ผู้เล่นเดินจริงด้วย**

## 13. ทิศทางศิลป์

**พิกเซลอาร์ต โทนจิบลิ · Godot 4 · 2D**

เลือกพิกเซลแทนภาพวาดมือเต็มรูปแบบ เพราะพิกเซลจากหลายแหล่ง**กลืนกันได้** ส่วนภาพวาดมือจากคนละมือจะเห็นรอยต่อทันที — สำคัญมากสำหรับโปรเจกต์ที่ต้องผสมแพ็กสำเร็จกับงานสั่งวาด

### จิบลิแปลเป็นข้อกำหนดจริง

| ลักษณะจิบลิ | แปลเป็นสิ่งที่ทำได้ |
|---|---|
| แสงอบอุ่นนุ่ม | 2D light + bloom อ่อน · ห้ามใช้เงาคมดำ |
| ธรรมชาติรกรุงรัง | ชั้นหญ้า/ใบไม้ที่ไหวตามลม (shader ไม่ใช่อาร์ต) |
| ท้องฟ้าเป็นตัวละคร | ฉากหลังไล่สี + เมฆเคลื่อน |
| สีเอิร์ธโทนอิ่มตัว | พาเลตต์ล็อก 32-40 สี ไล่โทนเขียว-ทอง-ฟ้า |
| ความเงียบและพื้นที่ว่าง | อย่ายัดรายละเอียดเต็มจอ ให้มีที่ว่างให้ตาพัก |

### พาเลตต์เปลี่ยนตามองก์ — งานหลักของทิศทางศิลป์นี้

```
องก์ 1 (EC 0-4)    เขียวชอุ่ม ฟ้าใส ทองอุ่น       จิบลิเต็มรูปแบบ
องก์ 2 (EC 5-10)   ลดความอิ่มตัว 15% ฟ้าเริ่มหม่น
องก์ 3 (EC 11-16)  เทาอมน้ำตาลเข้ามาแทนเขียว
ตอนจบ (EC 17+)     เถ้าและสนิม เหลือเขียวเป็นจุดๆ
```

ทำด้วย **color grading + เปลี่ยนแสง + สลับ prop** ไม่ใช่วาดใหม่ 36 ภาพ — แผนที่ 9 ผืน × 4 สถานะ ได้จากอาร์ต 9 ชุด

**และนี่คือเหตุผลที่จิบลิเป็นตัวเลือกที่ถูกต้อง** ยิ่งองก์แรกสวยและอบอุ่นเท่าไหร่ การเสื่อมสภาพยิ่งเจ็บเท่านั้น ผู้เล่นจะรู้สึกได้โดยไม่ต้องมีใครบอก

### สเปกที่ต้องล็อกก่อนสั่งงาน

```
ความละเอียดฐาน   320×180 หรือ 384×216 (ขยายเป็นจำนวนเต็มเท่านั้น)
ตัวละคร          32×32 (สำรวจ) · 64×64 (ต่อสู้)
มอนสเตอร์        64×64 ถึง 128×128 ตามขนาด
พาเลตต์          ล็อก 32-40 สี ใช้ร่วมกันทุกอาร์ต — ข้อนี้สำคัญที่สุด
การแยกชิ้นส่วน    หัว/ลำตัว/แขน/ขา แยก layer สำหรับ Skeleton2D
สัตว์ต้นแบบ       15 ตัว → แตกเป็นมอน 45 ตัวด้วย recolor + prop + สัดส่วน
```

**ห้ามวาดอนิเมชันทีละเฟรม** — 45 ตัว × 5 สถานะ × 8 เฟรม = 1,800 ภาพ ใช้ Skeleton2D + Polygon2D ขยับชิ้นส่วนแทน rig ชุดเดียวใช้ซ้ำได้กับตัวที่โครงร่างคล้ายกัน

### ลำดับการจ่ายเงิน

```
เดือน 1-4   ไม่จ่ายเลย · สี่เหลี่ยมสีล้วน · ทำ UI/แสง/เอฟเฟกต์/พาเลตต์เอง
จุดตัดสิน   ให้คนนอกเล่น vertical slice — สนุกจริงค่อยไปต่อ
หลังจากนั้น สั่งตัวอย่าง 1 ชิ้น (จ่ายเงิน) → พอใจค่อยสั่งครบ 15
```

**อาร์ตคือสิ่งสุดท้ายที่ซื้อ ไม่ใช่สิ่งแรก**

## 14. สิ่งที่ยังไม่ได้ตัดสินใจ

1. **แต้มสายพันธุ์ 8 หรือ 5** — รอวัดเมื่อมีมอนครบ 45 สายพันธุ์
2. **ความยาวเกม 12 ชม. หรือมากกว่า** — จำลองแล้วว่า 100 ชั่วโมงต้องใช้ศึก 1,477 ครั้ง = 7.8 เท่าของเนื้อหาที่ออกแบบ และระบบไม่ให้รางวัลกับการวนซ้ำอยู่แล้ว **ถ้าอยากได้ 100 ชั่วโมง ให้มาจากการเล่นซ้ำ 6-8 รอบ ไม่ใช่จากการยืดรอบเดียว** (ดีไซน์รองรับอยู่แล้ว: เห็น 14/24 เควส · รับมอน 4/20 · 4 ตอนจบ · NG+)
3. **ความยากจริงสำหรับผู้เล่นที่เล่นเป็น** — ตัวเลขทั้งหมดในเอกสารนี้วัดจาก AI จำลอง ซึ่งเล่นแย่กว่าคนจริงมาก (ดู 11.19) **ต้องมีคนเล่นจริงก่อนจะสรุปว่าสมดุลถูกต้อง**
4. **แพ็กอาร์ตฐาน** — ต้องเลือกแพ็กพิกเซลโทนอุ่นหนึ่งชุดแล้วยึดทั้งเกม (OpenGameArt CC0 · itch.io · **ระวัง LPC เพราะ CC BY-SA ติดไวรัส**)
5. **จ้างวาดหรือหาหุ้นส่วนแบ่งรายได้** — ตัดสินหลังผ่านจุดตัดสิน ไม่ใช่ตอนนี้
