## กติกาที่ใช้ทุกหัวข้อ (เหมือนรอบแรก)

1. ทุกข้ออ้างที่มาจากแหล่งภายนอก ใส่ **[อ้างอิง]** + URL ท้ายหัวข้อ · ที่คิดเอง/อนุมาน ใส่ **[การอนุมาน]**
2. หาไม่เจอ → เขียนตรงๆ ว่า "ไม่พบ" **ห้ามแต่งชื่อเกม/อนิเมะ/ตัวเลข**
3. ตัวเลขเฟรมทั้งหมดเป็นหน่วย "เฟรม 60 ms" ของเกมเรา · ถ้าแหล่งอ้างอิงใช้หน่วยอื่น (เช่น เฟรม 60 fps ของเกมต่อสู้) ให้ใส่ทั้งค่าเดิมและค่าที่แปลงแล้ว (60 fps 1 เฟรม = 16.7 ms → ÷3.6)
4. ขนาดทุกอย่างเป็น "พิกเซลบนเวที 300 × 168" ไม่ใช่ % จอ
5. ส่งผลเป็น **ไฟล์ HTML ไฟล์เดียว** แบบรอบแรก และใส่ข้อมูลดิบเป็น JSON ในแท็ก `<script>` ชื่อ `const R2 = {...}` ตามโครงที่ระบุใต้แต่ละหัวข้อ (ฝั่งเกมจะดึง JSON ไปใช้ตรงๆ)
6. ภาษาไทย · ศัพท์เฉพาะใส่อังกฤษ/ญี่ปุ่นในวงเล็บได้

## หัวข้อ 1 (สำคัญที่สุด) — รายการภาพที่ต้องเจน PixelLab ต่อท่า

**เป้าหมาย:** รู้ก่อนเจนว่าแต่ละท่าต้องเจนภาพใหม่กี่ภาพ ภาพไหนใช้ของเดิมได้ เพื่อประหยัดโควตา

ทำทั้ง 102 ท่า (เรียงตามสาย · เริ่มจากสายคม bl0–bl16 ก่อน แล้วค่อยสายอื่น):

3. เทียบกับ **ตารางชุดภาพที่มีแล้ว** (หัวข้อ 0) แล้วบอกว่า: ใช้ภาพเดิมชุดไหน ภาพที่เท่าไร ได้เลย / ใช้ได้ถ้าโค้ดหมุน·พลิก·ยืด / ต้องเจนใหม่
4. ภาพที่ต้องเจนใหม่: เขียน **คำบรรยายสำหรับ PixelLab** เป็นภาษาอังกฤษ 2–4 ประโยค ระบุทิศ (facing left/west, side view) · ของในมือ (kitchen knife in RIGHT hand, blade length ~ forearm) · ท่าตัวทีละส่วน · สิ่งที่ห้าม (no motion lines, no glow, no second weapon, do not face camera)
5. ประเมินความเสี่ยงของภาพนั้นกับ PixelLab (ต่ำ/กลาง/สูง) ตามบทเรียนข้างบน และถ้าสูง เสนอทางเลี่ยง (เช่น แยกเป็น 2 ท่าค้าง แล้วให้โค้ดเชื่อม)

## หัวข้อ 2 — ปฏิกิริยามอนตามชนิดร่างกาย × ชนิดการโจมตี

**เป้าหมาย:** ฉากของเราคำนวณจากภาพมอนเองจึงใช้ได้ทุกตัว แต่ท่าโดน/ท่าตายยังมีแค่ไม่กี่แบบ ต้องการ "คู่มือปฏิกิริยา" ที่โค้ดเอาไปใช้ได้

ตาราง 9 ร่างกาย (เนื้อ เกราะ วิญญาณ ปีก นุ่ม กระดูก ไม้ หิน กลไก) × 6 การโจมตี (คม ทุบ แทง ยิง กล(ไฟฟ้า/กลไก) มือเปล่า) = 54 ช่อง แต่ละช่องระบุ:
1. **ตอนโดน:** ตัวขยับอย่างไร (ผงะ ยุบ บิด กระเด็น ไถล — กี่พิกเซล กี่เฟรม) · สิ่งที่กระเด็นออก (เลือด เศษ ประกายไฟ เมือก ผง ไอ — สี จำนวน ทิศ แรงโน้มถ่วง) · รอยที่ค้างบนตัว (แผล ร้าว บุบ รู) อยู่นานแค่ไหน
2. **ตอนตาย (KO):** สลายแบบไหน (แตกเป็นก้อน ไหลเยิ้ม ผงลอยขึ้น ปลิวร่วง ระเบิดเฟือง ไฟดับ ฯลฯ) · ลำดับจังหวะเป็นเฟรม
3. **เสียงโดน** เป็นสูตร N/T (หัวข้อ 0) อย่างน้อย 1 สูตรต่อร่างกาย และระบุว่าการโจมตีชนิดไหนต้องเพิ่ม/เปลี่ยนชั้นเสียงอะไร
4. **เหตุผลจากของจริง:** อ้างอิงฟิสิกส์/วัสดุ/สัตววิทยา (เช่น เปลือกแข็งแตกแบบเปราะ, ไม้แตกตามเสี้ยน, ผ้าไหม้/เนื้อฉีก) และเกม/อนิเมะที่ทำปฏิกิริยาแบบนั้นได้ดี (มีหลักฐาน)
5. **กรณีพิเศษ:** มอนบินได้ (ปีก) โดนแล้วร่วงหรือไม่ · มอนวิญญาณโดนคม/ทุบ "ไม่ควรมีเลือด" ควรเห็นอะไรแทน · บอสตัวใหญ่ (96 พิกเซล) ปฏิกิริยาต้องหนัก/ช้ากว่าตัวเล็กเท่าไร
6. ข้อจำกัด: เกมนี้ไม่เน้นความรุนแรงเลือดสาด — เลือดเป็นพิกเซลแดงเข้มไม่กี่จุด ไม่มีชิ้นเนื้อ (ยกเว้นเสนอให้ปรับแล้วให้เหตุผล)

## หัวข้อ 3 — ตัวเลข "ความหนัก" ตอนโดน (game feel) จากเกมอ้างอิงจริง

**เป้าหมาย:** ตอนนี้ค่าเหล่านี้ตั้งด้วยความรู้สึก (หยุดภาพ 0.06–0.12 วินาที จอสั่น 1.5–4 พิกเซล มอนกระเด็น 3–10 พิกเซล) ต้องการตัวเลขที่มีที่มา

1. **หยุดภาพ (hit-stop / hit-lag)** — ค่าจริงจากเกมที่เปิดเผยข้อมูล: Street Fighter (II/IV/V/6), Guilty Gear, Smash Bros. (สูตร hitlag ตามดาเมจ), Monster Hunter, Hollow Knight, Dead Cells, Celeste/Hades (ถ้ามี) และเกม JRPG ผลัดกันตีที่มีหยุดภาพ (Octopath Traveler, Sea of Stars, Persona 5 ฯลฯ ถ้าหาข้อมูลได้) — แยกตามความแรงของท่า (เบา/กลาง/หนัก/ไม้ตาย) และบอกว่าหยุดทั้งจอหรือหยุดเฉพาะผู้โจมตี/ผู้โดน
2. **จอสั่น** — ความแรง (พิกเซลบนจอ 300 × 168 หลังแปลง) · ระยะเวลา · รูปแบบ (สุ่ม/ทิศเดียว/ลดลงแบบไหน) · หลักการออกแบบ (เช่น ทิศสั่นตามทิศการโจมตี, trauma²)
3. **มอนกระเด็น (knockback)** ระยะและเวลากลับที่ · การวาบขาว (กี่เฟรม)
4. **สูตรแนะนำสำหรับเกมเรา:** ตารางผูกกับ "พลังท่า" (power 60–200 ในข้อมูลเกม) และ "ท่าต้นสาย/กลาง/ปลาย" → หยุดภาพกี่เฟรม จอสั่นกี่พิกเซล กระเด็นกี่พิกเซล
5. **ข้อควรระวัง:** หยุดภาพนานเกินทำให้ท่าหลายฮิต (เช่น เขี้ยวพัน 3 ครั้ง) ช้า/อืด — ท่าหลายฮิตควรลดต่อฮิตอย่างไร (มีตัวอย่างจากเกมไหน)

โครง JSON:
```
R2.feel = { "refs": [ { "game": "...", "light": { "hitstop_ms": 0, "shake_px": 0 }, "heavy": {...}, "notes": "...", "url": "..." } ],
   "recommend": [ { "power_min": 60, "power_max": 100, "tier": "ต้นสาย", "hitstop_frames": 1, "shake_px": 1.5, "shake_frames": 4, "knockback_px": 4, "flash_frames": 2 } ],
   "multi_hit_rule": "..." }
```

## หัวข้อ 4 — ความปลอดภัยเรื่องแสงวาบ (photosensitive epilepsy)

**เป้าหมาย:** หลายท่าของเรามีจอวาบขาวทั้งจอ (ผ่าเกราะตอนเกราะแตก · ฉากประกายตอนเวลาหยุด · จันทร์เสี้ยว) และตัวมอนวาบขาว 2 เฟรมทุกครั้งที่โดน ต้องรู้ว่าปลอดภัยไหม

1. เกณฑ์มาตรฐาน: WCAG 2.x (Three Flashes or Below Threshold · general flash / red flash threshold · พื้นที่ 25% ของมุมมอง) · ITU-R BT.1702 / Ofcom · Harding test · แนวทางของ Xbox Accessibility Guidelines / Game Accessibility Guidelines — ตัวเลขที่ชัดเจน: กี่ครั้งต่อวินาที ความสว่างเปลี่ยนเท่าไร พื้นที่เท่าไร แดงอิ่มเป็นกรณีพิเศษอย่างไร
2. แปลงเป็นกฎสำหรับเกมเรา: จอ 300 × 168 · 60 ms/เฟรม → "วาบได้ไม่เกินกี่ครั้งในช่วงกี่เฟรม" "พื้นที่วาบกี่พิกเซล" "ความทึบ (alpha) เท่าไรถึงไม่นับเป็นวาบ"
3. ตรวจท่าที่มีอยู่ตามคำอธิบายนี้ (ใช้ข้อมูลรายงานรอบแรกส่วนที่ 2 ประกอบ):
   - ผ่าเกราะ bl8: จอขาวทั้งจอ alpha 0.22 → 0.11 สองเฟรม · ตัวมอนวาบขาวเต็ม 3 ครั้งในราว 25 เฟรม
   - ประกาย: จอขาวทั้งจอ alpha 0.6 → 0.3 สองเฟรม แล้วจอมืดคราม 0.66 ค้าง 34 เฟรม · หลอดไฟกะพริบ 2 ครั้ง (เฟรม 10, 12)
   - จันทร์เสี้ยว bl9: พระจันทร์ + รอยฟันวาบ 2 เฟรม · ตัวมอนวาบขาว 2 เฟรม
   - เขี้ยวพัน bl2: วาบขาวตัวมอน 4 ครั้งในราว 37 เฟรม (3 ฟัน + แตก) · มอนเลือดไหลกะพริบแดงอ่อน (alpha 0.05–0.12) ทุก ~12 เฟรม
   บอกว่าข้อไหนผ่าน/เสี่ยง/ไม่ผ่าน และควรแก้อย่างไร
4. ตัวเลือก "ลดแสงวาบ" ในเมนูตั้งค่า: เกมอื่นทำอย่างไร (มีตัวอย่างจริง) ควรแทนที่ด้วยอะไร (หรี่ · สีอื่น · ขอบเรือง · หยุดภาพแทน)

โครง JSON:
```
R2.flash = { "rules": [ { "source": "WCAG 2.3.1", "rule": "...", "for_us": "..." } ], "game_rule": { "max_flash_per_window": 3, "window_frames": 17, "max_area_px": 12600, "safe_alpha": 0.1 },
   "audit": [ { "scene": "bl8", "verdict": "pass|risk|fail", "why": "...", "fix": "..." } ], "option_examples": [ { "game": "...", "what": "...", "url": "..." } ] }
```

## หัวข้อ 5 — ชั้นเจาะลึก + ชั้นนำเสนอ ของอีก 5 สาย (ทุบ แทง ยิง กล มือเปล่า)

**เป้าหมาย:** รอบแรกทำ "เจาะลึก (รอบ 2)" และ "นำเสนอ (รอบ 3)" ให้เฉพาะสายคม 17 ท่า — ขอแบบเดียวกันให้ครบอีก 85 ท่า

- โครงเหมือนของสายคมทุกประการ: กายวิภาคทีละจังหวะ · โมเมนตัมและทิศทาง · เอฟเฟกต์ที่ควรจะเป็น · ปฏิกิริยามอน · ข้อเสนอปรับ · บรรยากาศ · เสียงทีละจังหวะ · VFX 5 จังหวะ (รวมพลัง → ปล่อย → เดินทาง → กระทบ → หาง) · โทนสี · timing/game feel
- **เสียงต้องเขียนเป็นสูตร N/T ตามหัวข้อ 0** (ความถี่ ความยาว ความดัง ชนิดกรอง) ต่ออีเวนต์ต่อเฟรม — ไม่ใช่คำบรรยายอย่างเดียว
- **อาวุธของเราเป็นของใช้ในชีวิตประจำวัน** (ไม้เบสบอล ดินสอ หนังสติ๊ก ที่เย็บ ถุงมือ) — ปรับกลไกศาสตร์จริงให้เข้ากับขนาด/น้ำหนักของของจริงเหล่านี้ และบอกตรงๆ ถ้าท่าไหนอาวุธในเกมเล็ก/เบาเกินจะทำท่าแบบศาสตร์ต้นฉบับได้
- สายยิงกับสายกล: มี "สิ่งที่พุ่งออกไป" (ก้อนหิน ลูกเย็บ) — ระบุขนาดพิกเซล ความเร็ว (พิกเซล/เฟรม) วิถี (ตรง/โค้ง) และเฟรมที่ปล่อย/ถึงเป้า

โครง JSON: ใช้โครงเดียวกับ `DEEP` และ `PRESENT` ของรายงานรอบแรก (คีย์ = รหัสท่า) เพิ่ม `"sfx": [ { "frame": 12, "recipe": "N(...)" } ]`

## หัวข้อ 6 — ท่าโจมตีของมอนรายตัว (45 ตัว + บอส 5)

**เป้าหมาย:** ตอนนี้มีแค่ M01 สไลม์ "กระดึ๊บ 2 ครั้ง → ถีบพุ่งกระแทก" (92 เฟรม) — ต้องการท่าโจมตีปกติของมอนทุกตัว + ท่าเด่น (signature) ในตาราง

1. **ท่าโจมตีปกติ** อิงสัตว์/สิ่งที่มอนเป็นจริง (หมาป่ากระโจนกัดคอ · ค้างคาวโฉบ · โครงกระดูกฟันดาบสนิม ฯลฯ) — อ้างอิงพฤติกรรมจริง (สัตววิทยา) หรือนิทาน/ตำนานต้นแบบ
2. **แผนเฟรม 60 ms** (เข้าประชิดหรือไม่ · ง้าง · กระทบ เฟรมไหน · กลับที่) และระบุว่าใช้ภาพมอน 8 ภาพที่มี (idle×3 wind atk follow hurt ko) ภาพไหนตอนไหน — **ถ้าต้องมีภาพเพิ่ม ให้บอกว่าภาพอะไร กี่ภาพ**
3. **ท่าเด่น (signature)** ตามชื่อในตาราง: ออกแบบแผนเฟรม + VFX + เสียง (สูตร N/T) แบบย่อ
4. ปฏิกิริยา Rion: โดนตี / ตั้งรับ แบบไหนเหมาะกับท่านั้น (ใช้ภาพ pls_hurt / pls_guard ที่มี)

## หัวข้อ 7 — VFX พิกเซลบนจอเล็ก: ขนาด สี และการอ่านออก

1. ศึกษาเกมพิกเซล 2D/HD-2D ที่มีฉากต่อสู้ผลัดกันตี: Octopath Traveler (I/II), Sea of Stars, Chained Echoes, Eiyuden Chronicle, Triangle Strategy, Romancing SaGa (Minstrel Song Remastered / 3 Remaster), Final Fantasy VI Pixel Remaster, Live A Live (HD-2D)
2. ต่อเกม: ความละเอียดภาพจริง (พิกเซลเกม) · ขนาดตัวละคร (พิกเซล) · ขนาดเอฟเฟกต์ฟัน/ระเบิด/เวทเทียบตัวละคร (เท่าตัว) · จำนวนสีในเอฟเฟกต์ · ใช้แสงบวก/เรืองแสง/เบลอหรือไม่ (ผสมพิกเซลกับเอฟเฟกต์ความละเอียดสูงไหม) · เอฟเฟกต์บังตัวละครนานแค่ไหน
3. **ตัวเลขข้อความบนจอ:** ขนาดตัวเลขดาเมจ ป้ายชื่อท่า (พิกเซลสูง) ค้างกี่วินาที ตำแหน่ง — เพื่อเทียบกับของเรา (ตัวเลข 14 px · ป้ายเสียง 12 px · ป้ายชื่อท่า 12 px บนจอ 168 px)

5. หาภาพ/วิดีโอตัวอย่างจากแหล่งที่เปิดเผย (ลิงก์) — ไม่ต้องฝังภาพลงไฟล์
